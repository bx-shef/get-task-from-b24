# Деплой

> Last reviewed: 2026-08-26

Схема та же, что в `client-bank-alfa-by`: **CI собирает образ → GHCR → Watchtower на
сервере подхватывает → общий nginx-proxy отдаёт наружу по TLS**. Ручных шагов на сервере
после первичного развёртывания нет.

> ⬜ **Дозаполняется** вместе со стеком: содержимое `Dockerfile`, список переменных
> окружения, состав `docker-compose.prod.yml`. Схема при этом уже зафиксирована —
> менять её без причины не нужно.

## Конвейер

```
PR      → ci (линт + типы + тесты) + сборка образа без push
main    → ci → build & push в ghcr.io/bx-shef/get-task-from-b24:latest
сервер  → Watchtower видит новый образ (~5 мин) → перезапускает контейнер
```

⚠ **Деплой гейтится зелёным `ci`** (`needs: ci` у джобы деплоя): красная сборка не
доезжает до реестра, а значит и до сервера. Это единственное, что отделяет «сломал
тесты» от «сломал прод».

⚠ **Сторонние actions пинуются по полному SHA коммита**, а не по тегу: тег изменяем
владельцем действия, и подменённый тег выполняет чужой код на раннере с `GITHUB_TOKEN`.
Комментарий `# vX.Y.Z` рядом с SHA читает Dependabot и держит пины свежими — то есть
пиннинг ничего не стоит в сопровождении.

## Сервер

- Контейнер приложения за общим `nginx-proxy` + `acme-companion` (сеть `proxy-net`),
  TLS — Let's Encrypt. Reverse-proxy ставится на сервере один раз и обслуживает все
  проекты; здесь его не дублируем.
- `Watchtower` следит за образом и катит обновления сам.
- На сервере лежат ровно три файла: `docker-compose.prod.yml`, `Makefile`, `.env`.
  Репозитория и пакетного менеджера там нет.

## Команды на сервере — только через `make`

⚠ **Правило, а не пожелание.** Терминал у владельца бывает мобильным, а
продиктованная строка `docker compose …` не проверяема и живёт только в истории чата.
Любая операция обязана быть **одной вставляемой целью** `make`.

Порядок при добавлении операции:

1. скрипт в `scripts/` — чтобы он был проверяем и покрыт тестом;
2. цель в `Makefile`, тянущая скрипт из репозитория по тому же `REF`, что и `self-update`
   (иначе `Makefile` обновится из одной ветки, а скрипты приедут из другой);
3. строка `## описание` **вплотную** над целью — иначе она не попадёт в `make help`;
4. владельцу — `make self-update && make <цель>`.

**`make self-update` заводим первым.** `Makefile` кладётся на сервер один раз при
развёртывании и дальше живёт своей жизнью: без цели, которая обновляет его самого,
все остальные цели бесполезны. Скачанное проверяем **до** замены и сохраняем копию
прежнего — битый `Makefile` лишает сервер единственного интерфейса.

⚠ **Параметры `make` передаём ПЕРЕД командой** (`DAY=… make цель`), а не после.
Значение параметра, заданное как `make цель VAR=…`, раскрывается до всякого шелла —
включая режим `-n`: осторожный «сперва посмотрю, что будет» детонирует вместо того,
чтобы защищать. Параметр ветки (`REF`) поэтому задаётся в файле жёстко и из командной
строки не переопределяется.

## Первичное развёртывание

⬜ **Дозаполняется.** Форма раздела: скопировать `docker-compose.prod.yml` + `Makefile`,
завести `.env` (список переменных с пометкой, какие обязательны в проде и что тихо
ломается без них), поднять, проверить health-эндпоинт.

⚠ Переменную, без которой приложение **стартует, но работает неправильно**, помечаем
здесь явно. Авария от такой переменной тихая и отложенная — её находят через неделю по
последствиям.

## Откат

⬜ **Дозаполняется.** Минимум: закрепить предыдущий тег образа (`sha-…`) вместо
`latest`, перезапустить, убедиться по health. Откат должен быть одной целью `make`.
