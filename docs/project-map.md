## Цель

Сетевой обработчик, который ловит создание задачи на портале клиента Битрикс24,
проверяет критерии и заводит задачу в нашем Битрикс24 + шлёт сигнал в Telegram.
Порталов клиентов — **20–30**, список в переменных окружения.

Критерии, перенос полей и поведение при ошибках — [`PROCESSING.md`](PROCESSING.md).

## Что мешает

Запуск состоялся; открытым остаётся немногое:

- ⬜ Настройки GitHub из [`REPO_SETUP_CHECKLIST.md`](REPO_SETUP_CHECKLIST.md) (защита
  `main`, `ci` как required-check) — владелец делает 2026-08-27.
- ⚠ **Адрес сервиса попадает в форму локального приложения у КАЖДОГО клиента**, и его
  смена потребует участия каждого из них. Менять домен теперь дорого.
- ⬜ Неверный id группы портал молча принимает: `make client-add` проверяет только, что
  это число. Ошибка вскроется задачами в чужой группе — смотреть `groupId` в строке
  лога `created`.
- ✅ **Замер скоупа снят:** право называется `task`, `tasks.task.get` работает.
- ⬜ **Второй замер ждёт своего часа:** форма обмена refresh-токена (POST против GET)
  вскроется примерно через час после установки, когда токен впервые протухнет.
- ✅ **Telegram доходит:** сообщение о созданной задаче приходит в группу владельца.
