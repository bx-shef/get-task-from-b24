# CLAUDE.md

> Last reviewed: 2026-08-26

Сервис-посредник между двумя порталами Битрикс24: принимает вебхук о создании задачи
на портале-источнике и заводит задачу на портале-приёмнике.

> **Статус: 🧪 код собран и под тестами, вживую на порталах не гонялся.** Сквозной путь
> (установка → событие → очередь → создание задачи → Telegram) проверен на локальном
> стенде против несуществующего портала: авторизация события, дедуп и ретраи ведут себя
> как задумано, но НИ ОДНА задача ещё не переехала между настоящими Б24.
>
> ⚠ **Правило этого документа: утверждаем только проверенное.** Формулировка «сделано»
> означает «прогнано вживую», а не «код написан». Для второго есть 🧪. Расхождение
> между прозой и кодом обнаруживается случайно и стоит дорого — см. легенду статусов в
> [`docs/project-map.md`](docs/project-map.md).

## Стек

Зафиксирован владельцем 2026-08-26 — тот же, что в `client-bank-alfa-by`, минус фронтенд
(интерфейса у сервиса нет):

| Что | Чем | Почему именно так |
|---|---|---|
| рантайм | **Node 22 LTS** + **pnpm** (через corepack, версия в `packageManager`) | как в соседнем проекте: одни привычки, один деплой |
| сервер | **Nitro** (без Nuxt) | нужны только HTTP-роуты; фронтенд-фреймворк здесь лишний слой |
| база | **Postgres** | токены порталов продлеваются в рантайме, журнал переносов обязан переживать перезапуск |
| очередь | **Redis + BullMQ** | события Б24 **не ретраятся** — приём и обработка обязаны разъехаться |
| тесты | **Vitest** | |
| линт | **ESLint** | |

⚠ **`typescript` ограничен линией 6.x** (`^6.0.3`), и мажор у него в `ignore` у
Dependabot. `typescript-eslint` отказывается работать с TS 7 («does not support TS 7.0»),
то есть на последней версии линт не запускается вообще. Снимать ограничение — когда
`typescript-eslint` научится TS 7, и не раньше.

⚠ **Очередь здесь не «для масштаба», а по существу задачи.** Обработчик обязан ответить
200 до всякой работы, иначе задача клиента теряется молча и навсегда.

## Команды

| Команда | Что делает |
|---|---|
| `corepack enable && pnpm install` | установка зависимостей |
| `docker compose up -d db redis` | локальные Postgres и Redis |
| `pnpm dev` | дев-сервер (`:3000`) |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm test` | Vitest |
| `pnpm check` | всё сразу — **это же гоняет CI** |
| `pnpm build` | сборка Nitro в `.output/` |

Перед пушем — зелёный `pnpm check`.

## Архитектура

**Чистые ядра — в `src/domain/`, побочные эффекты — тонким слоем поверх.** Всё, что
можно проверить без сети, базы и портала, проверяется без них.

| Файл | За что отвечает | Что в нём легко сломать |
|---|---|---|
| `server/routes/b24/handler.post.ts` | приём `ONTASKADD` и `ONAPPUNINSTALL`: сверка `application_token` → очередь → **200 сразу** | любая работа до ответа. ⚠ События Б24 **не ретраятся**: медленный ответ = потерянная задача |
| `server/routes/b24/install.post.ts` | `ONAPPINSTALL` и `ONAPPUPDATE`: доказать токен вызовом `app.info` на портал **из реестра**, сохранить, подписать события | порядок проверок: в базу пишем только после доказательства. Упавший `event.bind` не должен стирать уже сохранённые токены |
| `server/routes/health.get.ts` | живость: база и Redis | Redis обязан проверяться: сервис с мёртвым Redis принимает события и молча их теряет |
| `server/plugins/bootstrap.ts` | старт: конфиг → миграции → очереди → воркеры | воркеры живут в том же процессе |
| `src/config.ts` | чтение окружения | переменная, без которой сервис **стартует, но работает неправильно** |
| `src/runtime.ts` | контекст процесса (конфиг, пул, очереди) одним синглтоном | инициализация до первого запроса; без неё роуты падают с «контекст не инициализирован» |
| `src/store/db.ts` | нумерованные миграции под advisory-lock, лок по ключу | миграции гоняются **на каждом старте**; шаги только добавляются в конец, менять применённые нельзя |
| `src/store/portalTokens.ts` | токены порталов, сверка `application_token` | токены шифруются; сверка токена — по хэшу и постоянного времени |
| `src/notify/telegram.ts` | отправка сообщений | без `parse_mode`: символы из чужого заголовка ломали бы разметку |
| `src/domain/portals.ts` | реестр порталов из `B24_PORTAL_*` | нормализация домена: без неё событие не находит свой портал |
| `src/domain/criteria.ts` | критерии `#support` + «особый» исполнитель | срезка префикса не должна давать пустое название |
| `src/domain/taskMapping.ts` | сборка задачи для нашего портала | постановщик и исполнитель — **не** id с портала клиента |
| `src/domain/telegramMessage.ts` | тексты сообщений | сообщение об аварии без портала и id бесполезно |
| `src/crypto.ts` | AES-256-GCM для токенов, хэш `application_token` | сравнение токена — постоянного времени |
| `src/b24/eventPayload.ts` | разбор тела события | портал шлёт **форму**, а не JSON |
| `src/b24/rest.ts`, `errors.ts` | вызовы порталов, allow-list сервера авторизации, что повторять | повтор невосстановимой ошибки прячет аварию от человека; за редиректами не ходим — 307 увёл бы `client_secret` |
| `src/http/readLimitedBody.ts` | потолок тела, потоком | считать байты **до** буферизации, иначе защита только на бумаге |
| `src/b24/portalClient.ts` | токены портала и их продление | ровно одна повторная попытка после продления |
| `src/b24/tasks.ts` | `tasks.task.get` / `tasks.task.add` / `user.get` | портал отдаёт id **строками** |
| `src/store/transfers.ts` | журнал переносов | дедуп держится на первичном ключе базы, а не на проверке перед вставкой |
| `src/queue/*` | BullMQ: очередь событий и очередь уведомлений | `jobId` не может содержать `:` |
| `src/pipeline/transfer.ts` | порядок переноса целиком | занять журнал **до** создания задачи |

Спецификация — [`docs/PROCESSING.md`](docs/PROCESSING.md), контракт событий и методов —
[`docs/B24_EVENTS.md`](docs/B24_EVENTS.md), сторона клиента —
[`docs/CLIENT_APP.md`](docs/CLIENT_APP.md).

## Процесс разработки

Полностью — в [`docs/PROCESS.md`](docs/PROCESS.md). Коротко, и это правила, а не пожелания:

1. Ветка от `main`, работа в ней. **В `main` не пушим — только через PR.**
2. Перед PR — зелёный `check` локально.
3. **Панель из 5 проверяющих** (корректность · тесты · интеграция/контракты ·
   безопасность/ПДн · тех-дир), замечания устраняются **до** мержа.
4. PR → зелёный CI (`ci` — required status check) → **squash-merge**, ветка удаляется.
5. Деплой — автоматом с `main`, см. [`docs/DEPLOY.md`](docs/DEPLOY.md).

## Деплой

Так же, как в `client-bank-alfa-by`: образ собирается в CI, публикуется в **GHCR**, на
сервере его подхватывает **Watchtower** за общим **nginx-proxy** (TLS — Let's Encrypt).
Деплой гейтится зелёным `ci`: красная сборка не доезжает до реестра. Подробности и
переменные — [`docs/DEPLOY.md`](docs/DEPLOY.md).

**Команды на боевом сервере — только через `make`.** На сервере нет ни репозитория, ни
пакетного менеджера: только `docker-compose.prod.yml`, `Makefile` и `.env`. Любая
операция обязана быть одной вставляемой целью `make`, а не продиктованной строкой
`docker compose …`. Первой целью заводится `make self-update` — без неё остальные
бесполезны, потому что `Makefile` кладётся на сервер один раз и дальше не обновляется.

## Конвенции

- **Пользовательский текст, README и документация — на русском** (их читает владелец и
  клиент). Комментарии и JSDoc — на языке ближайшего окружения; смешение языков внутри
  одного модуля — дефект чтения.
- Чистые функции выносим отдельно и покрываем тестами; побочные эффекты (REST-вызовы,
  запись в БД) — тонким слоем поверх них.
- **Секреты — только через окружение.** Ни токенов, ни адресов порталов в коде,
  в тестах и в логах. Персональные данные сотрудников из задач (ФИО, контакты) в
  телеметрию и спаны не кладём.
- **Учёт исходящих REST-методов Б24** ведём в [`docs/B24_EVENTS.md`](docs/B24_EVENTS.md):
  добавили метод — добавили строку. Иначе список нужных приложению прав собирается
  по коду вручную и всегда с ошибкой.
- **Штамп ревью:** каждый `.md` в корне и в `docs/` несёт строкой сразу под H1
  `> Last reviewed: YYYY-MM-DD`. Ключ на английском (технический маркер), дату бампим
  при содержательной правке. Наличие штампа проверяет `tests/mdReviewStamp.test.ts`.
- **Один факт — одно место.** Продублированные утверждения расходятся молча.
